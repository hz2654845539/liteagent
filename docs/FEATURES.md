# LiteAgent 功能说明书

> 版本 0.1.0 · 2026-10-17
> 对象：使用者 / 面试官 / 后续维护者

---

## 一、这是什么

一个**完全离线的手机 AI 助理**。模型下载到手机上，推理在本地跑，文档不出设备。

它能做四件事：

1. **聊天**——断网也能用，流式输出，随时可停
2. **读你的文件**——导入 txt / md，提问时自动检索，回答标注来源
3. **替你动手**——设提醒、读剪贴板、看今天日程
4. **自己选模型**——按手机配置自动挑 0.5B / 1.5B / 3B，也可以手动换

---

## 二、三分钟上手

```
1. 安装 APK（arm64 手机，Android 8.0+）
2. 打开后首页顶部会显示推荐模型，点「下载模型」（531MB ~ 2.2GB，支持断点续传）
3. 下载完点「加载模型」，等 1-3 秒，输入框亮起
4. 输入「你好」
```

首次使用建议按这个顺序体验：

```
对话 → 选「翻译」人格 → 长按复制回答 → 退出重进（对话还在）
资料库 → 添加文档 → 回对话问「文档里说了什么」
跑分 → 跑一轮 → 复制 Markdown
```

## 四、功能详解

### 4.1 对话

**做什么**：本地模型流式生成回答。

**怎么用**：输入问题 → 发送。生成中按钮变「停止」，点一下立刻停。

**技术细节**：MNN 没有回调式 API，流式是靠「先 prefill（`max_new_tokens=0`）再逐 token `generate(1)`」实现的。停止的最坏延迟是一个 token 的解码时间（约 100ms）。

**失败时**：模型未加载时输入框禁用，显示「先加载模型」。

---

### 4.2 人格预设

**做什么**：四套预设的 system prompt，切换后回答风格明显不同。

| 预设 | 行为 |
|---|---|
| 🤖 助理 | 通用问答，不确定就说不确定 |
| 🌐 翻译 | 只输出译文，不解释、不加引号 |
| ⌨ 代码 | 优先给能直接跑的代码，说明关键决策理由 |
| 📋 总结 | 压缩成三条要点，不写"综上所述" |

**怎么用**：左上角点预设名 → 选一个。

**注意**：切换预设会**清空当前上下文的 KV cache**。因为换人格等于换角色，带着上一个人格的历史去扮演新人格，输出会飘。

**会话记录不会丢**——历史消息还在，只是模型不再"记得"它们。

---

### 4.3 会话管理

**做什么**：多会话，自动持久化，可切换、删除、导出。

**怎么用**：
- 「新对话」：开一个空会话
- 会话名下拉：切换历史会话，每项右侧有删除按钮
- 「导出」：调起系统分享，输出 Markdown

**自动命名**：标题取第一条用户消息的前 20 字。没发消息前叫「新对话」。

**数据在哪**：`/data/data/<包名>/files/sessions/<id>.json`，退出 App 不丢。

---

### 4.4 模型管理

**做什么**：按设备配置推荐模型，支持下载、校验、切换、加载。

**推荐规则**（完整表在 `rules/recommend-rules.json`）：

| 实测总内存 | 模型 | 体积 |
|---|---|---|
| < 3.5 GB | **不推荐，明确拒绝** | — |
| ~3.5 GB | Qwen2.5-0.5B W4 | 531 MB |
| ~5.6 GB | Qwen2.5-1.5B W4 | 839 MB |
| ~7.5 GB | Qwen2.5-1.5B W4 | 839 MB |
| ~11.4 GB | Qwen2.5-3B W4 | 2.2 GB |

**为什么不用标称容量**：`MemoryInfo.totalMem` 比标称小 0.4–0.8GB，直接比阈值会让 6GB 机掉到最小模型。实现上先补偿 0.6GB 再就近归并档位。

**下载**：HTTP Range 断点续传，每个文件下完校验 SHA-256。`.part` 文件保留，下次从断点继续。

**切换**：对话页推荐那一行右侧「切换」，列出三个模型和体积。切换会先释放当前引擎——同时加载两个模型会把内存打爆。

**存放位置**：`/sdcard/Android/data/<包名>/files/models/<模型名>/`

---

### 4.5 文档问答（RAG）

**做什么**：导入手机里的文档，提问时自动检索相关片段，回答标注来源。

**怎么用**：
1. 资料库 Tab → 「添加文档」（系统文件选择器，不申请存储权限）
2. 回对话页正常提问
3. 回答下方会显示「来源：《方案.md》」
4. 长按可直接复制整段回答

**支持格式**：txt / md。**不支持 PDF**——`PdfRenderer` 只能渲染不能取文本，要引 PdfBox-Android（约 3MB），当前版本没做。

**分块策略**：按 Markdown 标题切分 → 按句累积到 400 字 → 保留相邻块一句重叠。

**检索**：BM25，中文用字级 bigram（"量化精度" → 量化/化精/精度），零词典依赖。

**关键行为**：**检索没命中时不拼任何资料**。宁可当普通对话，也不要把无关片段塞进上下文——那既浪费 prefill（手机上很贵），又会诱导模型硬套资料。

**回答约束**：prompt 里明确要求"只依据资料回答，资料里没有就说没有，并标注 [编号]"。

---

### 4.6 让助理动手（工具调用）

**机制**：不依赖模型原生 function calling（1.5B 上不稳定），而是让模型输出固定 JSON，客户端解析执行后回灌结果。

**三个工具**：

| 工具 | 触发方式 | 需要权限 |
|---|---|---|
| `set_reminder` | "明天下午三点提醒我开会" | 通知 + 精确闹钟 |
| `read_clipboard` | "看看我剪贴板里是什么" | 无（前台可用） |
| `list_today_events` | "我今天有什么安排" | 读日历 |

**执行流程**：
```
用户说话 → 模型输出 JSON → 客户端解析 → 执行 → 结果回灌 → 模型用人话总结
```

**容错**：解析器能处理模型加寒暄、套代码块、参数里带花括号、字符串里有转义引号。解析失败就当普通回复处理。

**降级**：拿不到精确闹钟权限时，不假装成功，而是返回"已设置，但系统未授予精确闹钟权限，实际可能延迟几分钟"让模型如实转述。

---

### 4.7 技能（Skills）

**做什么**：三个 Markdown 定义的工作流，命中关键词时注入 system prompt。

| 技能 | 触发词 | 产出 |
|---|---|---|
| 每日简报 | 简报 / 今天要做什么 | 今日重点 + 待办 + 一条建议 |
| 会议纪要 | 会议纪要 / 整理会议 | 主题 + 结论 + 待办表 |
| 文件归档 | 整理文件 / 归档 | 目录建议（**不自动移动文件**）|

**加新技能**：放一个 `.md` 到 `assets/skills/`，在 `SkillRouter` 里加一行触发词。不用改生成链路。

---

### 4.8 性能跑分

**做什么**：固定三条 prompt（短/中/长），测五项指标，可导出。

**指标来源**：全部取自 MNN 的 `LlmContext`，不是自己掐表：

| 指标 | 字段 |
|---|---|
| 模型加载 | `load_us` |
| prefill 速度 | `prompt_len / prefill_us` |
| 首 token | `ttfa_us` |
| decode 速度 | `gen_seq_len / decode_us` |
| 内存峰值 | `/proc/self/status` 的 `VmHWM` |

**为什么要 VmHWM**：端侧 LLM 的权重和 KV cache 全在 native 侧，`Runtime.maxMemory()` 反映不出来。

**导出**：「复制 Markdown」贴进 README/文档；「导出 JSON」存到 `files/benchmark/`。

## 五、权限清单

| 权限 | 用途 | 拒绝后 |
|---|---|---|
| INTERNET | 下载模型 | 无法下载，可手动 adb push |
| POST_NOTIFICATIONS | 提醒弹通知 | 提醒到点静默，无提示 |
| SCHEDULE_EXACT_ALARM | 准时触发提醒 | 降级为非精确闹钟，可能延迟几分钟 |
| READ_CALENDAR | 读今日日程 | 该工具返回"缺少权限" |

**没有申请**：存储权限（用 SAF）、位置、通讯录、相机、麦克风。

## 六、数据存在哪

全部在本机，位置是 App 私有目录（卸载即删除）：

```
files/models/       模型权重（531MB ~ 2.2GB）
files/documents/    导入的文档原文 + 索引
files/sessions/     对话记录
files/benchmark/    跑分结果
```

**唯一会外发的数据**：
- 模型下载请求（只发往 ModelScope，不带任何用户信息）
- 如果你手动配了后端地址，跑分数据会 POST 到 `/perf`

### 为什么模型放在应用私有目录，而不是 /sdcard

这台设备（DNAKE v911）的 `/data` 和 `/storage/emulated/0` **是同一块物理分区**：

```
/dev/block/mmcblk0p30  ext4   → /data
/dev/fuse                      → /storage/emulated（挂在这块分区上的视图）
```

所以放 `filesDir/models` 和放 `/sdcard/...` 用的是**同一份空间**。`df` 显示 `/storage/emulated` 25G 可用 21.5G，其中已经包含了应用占用的 531MB——不存在"24G 用不了"。

真正的差别是**访问路径**，不是空间：

| | `filesDir` | `/sdcard` |
|---|---|---|
| App 能否直接读写 | ✅ 无限制 | ⚠️ 受 FUSE / scoped storage 约束 |
| MNN 需要真实绝对路径 | ✅ | ❌ SAF 给的是 `content://` URI，MNN 读不了 |
| 用户能在文件管理器看到 | ❌ | ✅ |
| 卸载后清理 | ✅ 自动 | ❌ 可能残留 |

在这台设备上实测：App 读 `/sdcard/Android/data/<包名>/` 会被直接拒绝（`Permission denied`，用的是 App 自己的 uid），所以只能走私有目录。

**代价**：用户看不到模型文件。想手动换模型的话，目前只能通过 App 内下载。如果要支持"自己下载好放进去"，需要加一个 SAF 导入入口，把用户选中的文件复制进私有目录——这会多占一份空间（复制期间），所以没做。

**一个需要你知道的点**：`read_clipboard` 工具读到的内容会作为工具结果进入对话历史，随会话一起存在本地 JSON 里。如果剪贴板里有密码或验证码，它可能被存下来。当前版本**没有做脱敏**（只截断到 800 字）。

## 七、什么情况下不能用

| 情况 | 表现 |
|---|---|
| 内存 < 3.5GB | 推荐卡片直接显示"内存不足，无法运行端侧模型"，不提供下载 |
| 非 arm64 设备 | 装不上（只打 arm64-v8a） |
| x86 模拟器 | 装得上但加载模型失败（MNN 无 x86 的 `.so`）|
| 未下载模型 | 输入框禁用 |
| 模型文件损坏 | 加载失败，提示"文件缺失、损坏或内存不足"；重新下载会因 SHA-256 不匹配自动删除坏文件 |

## 八、已知限制

| 限制 | 原因 | 影响 |
|---|---|---|
| **真机推理未实测** | 手上没有 arm64 手机 | 所有性能数字留白 |
| 不支持 PDF | 需引 PdfBox（+3MB） | 扫描件、PDF 方案读不了 |
| 无向量检索 | 第一阶段只做 BM25 | 语义近似但用词不同的提问会漏 |
| 不吃 emoji | JNI 用 `NewStringUTF`（modified UTF-8） | 4 字节字符可能乱码 |
| 单会话无上限 | 每次全量写 JSON | 几千条消息时保存会变慢 |
| 无模型删除入口 | 未做 | 换模型后旧模型仍占空间，需手动清 |
| GPU 路径未验证 | 无真机 | OpenCL 可能负优化 |

---

## 九、一句话总结

**能离线聊天、能读你的文件、能替你设提醒、能在不同配置的手机上自己选模型——但还没有在真手机上跑出过第一个 token。**

最后这半句是这份说明书里最该被划重点的地方。
