# 11 · 整夜无人值守验证报告

> 时间：2026-10-17 23:46 → 10-18 00:33（约 47 分钟实际执行）
> 设备：一台国产安卓工控设备（adb 连接）
> 方式：全部自动化（autotest 参数 + uiautomator + 文件检查），用户睡觉，不打扰
> 结果：**10 项通过，3 个新 bug 修复，3 项无法自动化（原因明确）**

---

## 一、发现的 3 个新 bug（全部修复 + 复测）

### bug 1：send 没有任何异常保护（严重度：高）

`send()` 把 `generating = true` 之后，整个协程没有 try/finally。检索、工具执行、文件写入任何一处抛错 → 协程静默死亡 → `generating` 永久卡 true → **发送按钮永久变「停止」，会话废掉**。

**修复**：主体抽成 `runSendPipeline()`，外层包 `try / catch(CancellationException 重抛) / catch(Exception 显示 error) / finally 复位 generating`。

### bug 2：崩溃丢整轮对话（严重度：高，数据丢失）

实测：发问题 → 生成中 force-stop → 重启 → **会话 0 条消息，连用户打的问题都没了**。因为 `persistSession()` 只在 send 结束时调用。

**修复（三处）**：
1. 消息 append 后立即落盘一次
2. 启动恢复会话时过滤崩溃残留的空 assistant 占位
3. `switchSession` 加载时同样过滤

**复测**：崩溃后会话 2 条——USER 18 字问题保住 ✓，空占位被过滤 ✓。

### bug 3：切换人格预设被历史带偏（严重度：中）

翻译预设下输入 `hello world`，0.5B **顺着旧会话的历史继续聊 MNN**，完全无视翻译指令。切预设只改了 system prompt 和清 KV cache，**没清消息历史**。

**修复**：切预设时如果有历史，自动 `newSession()`（换角色语义上也是新对话的开始）。

**复测**：新会话 + 翻译预设 + `hello world` → 正确输出「你好，世界」✓。

## 三、1.5B 多轮压力实测（重要结论）

| 轮次 | ttft | prefill | decode |
|---|---|---|---|
| 1 | 29.4 s | 6.4 t/s | 3.0 t/s |
| 2 | 31.8 s | 7.0 t/s | 3.0 t/s |
| 3 | 43.0 s | 7.1 t/s | 2.7 t/s |

- **内存稳定**（PSS 1003–1058 MB，7 分钟无泄漏）
- **但 ttft 30–43 秒且随历史增长**，decode 3 t/s

**结论：1.5B 在这台设备上只适合单轮短问答，多轮不可用。** 设备分级里 1.5B 的「慢」警告应该加强为「多轮不推荐」。0.5B 仍是这台设备的主力。

## 四、无法自动化的（原因明确）

| 项 | 原因 | 替代方案 |
|---|---|---|
| 仅检索模式真机 | 设备输入框拿不到输入法焦点，`input text` 打不进字符；autotest 的 LaunchedEffect 在 Activity 重建后不触发 | **3 个单测已覆盖**（无命中提示 / 命中格式 / 多段编号） |
| 导出的实际分享 | 设备上没有任何可分享的目标 App | 面板正常弹出已验证，实际分享需人工 |
| 工具调用真机 | 极限档设计性禁用工具注入 | ToolRouter 依赖 Android API，JVM 单测覆盖不了 execute |

## 五、执行中踩的坑（对以后自动化有用）

1. **autotest 只在冷启动触发**：App 在前台时 `am start` 走 onNewIntent，LaunchedEffect 不重跑。每次要发消息都得先 `force-stop`。
2. **设备上预装的厂商对讲应用 会抢前台**：它是设备的常驻应用，测试中途会把 LiteAgent 顶出去，dump 之前要确认前台。
3. **屏幕会灭**：长时间等待后 `mCurrentFocus=null`，dump 是空的。每次 dump 前 `KEYCODE_WAKEUP`。
4. **adb pull 目标路径**：`MSYS_NO_PATHCONV=1` 下要用 `E:/...` 而不是 `/e/...`；pull 会保留源目录名（`.../sessions/` 多一层）。
5. **am start 的 --es 参数**：传中文长文本可行（1160 字成功），但 3000 字以上可能撞命令行长度限制。

## 八、已知局限（验证与截图过程中发现的）

1. **0.5B 的多轮记忆不稳定**：同一个记忆任务（记住 7391 → 重复），三次尝试只有一次答对，其余输出退化重复（"不确定"×48 / 编造 289 / 编造 12345679）。链路是通的（历史确实传到了模型，凌晨修复验证那次答对了），**但 0.5B 的记忆能力本身不可靠**。README 的多轮演示图放弃摆拍，以日志数据为准。
2. **设备上预装的厂商对讲应用 是设备常驻应用**：会把 LiteAgent 顶出前台（测试中多次发生）。对产品形态的含义：如果要在这种设备上做常驻 AI，得考虑与常驻应用的共存策略。
3. **1.5B 多轮不可用**（ttft 29–43s 且随历史增长），设备分级里它的描述应加强为"单轮短问答可用，多轮不推荐"。
